阅读中译本时对照原文发现了问题，欢迎提交。本站的性质和条目的读法见[关于](/about/)。

## 提交之前请准备好 {#prepare}

每一条都需要提供以下信息，便于他人核对：

1. **书目**：中译本的书名、译者、出版社，以及**版次和印次**。版次、印次印在版权页上，例如「2020 年 1 月第 1 版，2021 年 3 月第 3 次印刷」。不同印次的文字可能不同，所以印次不能省略。
2. **原书版本**：你对照的原书是哪个出版社、哪一年的版本。
3. **页码**：中译本页码和原书页码。
4. **引文**：原文和现译各引一两句。
5. **说明和依据**：问题在哪里，建议怎样译，依据是什么（词典义项、原始出处、通行译名等）。

## 三种参与方式 {#ways}

### 填写网上表单

有 GitHub 账号的话，这是最方便的方式。打开[提交新勘误]({{< param repo >}}/issues/new?template=new-erratum.yml)的表单，按栏目填写即可，不需要懂代码。注册 GitHub 账号是免费的。

### 发邮件 {#email}

不使用 GitHub 的话，请发邮件到 {{< email >}}，由维护者整理成条目。可以复制下面的格式填写：

```text
书名：
译者：
出版社：
版次与印次：
原书名与所据版本：
中译本页码：
原书页码：

原文：

现译：

类型（误译／漏译／专名与术语误识／可商榷／删节与改写对照）：

问题：

建议：

依据：

署名（希望在贡献者名单中显示的名字；不填则不列名）：

我同意以 CC BY-SA 4.0 授权本站使用我撰写的说明文字，并已阅读本页的写作要求。
```

维护者整理时，可能会按写作要求调整措辞，必要时会回信和你确认。

### 直接修改文件

熟悉 Git 的读者可以直接提交 pull request，文件格式和流程见仓库中的 [CONTRIBUTING.md]({{< param repo >}}/blob/main/CONTRIBUTING.md)。

## 指正已有条目 {#correct}

点条目页底部的「指正此条」，表单会自动填好条目的标题和链接。已对照原书核实了某一条，或者发现新印次已经改正，也请用这个表单告诉我们。不使用 GitHub 的话，发邮件时附上条目的链接即可。

## 收录原则 {#principles}

- 收录对照原文可以核对的问题：误译、漏译、专名与术语误识。
- 现译不能说错、只是另有值得考虑的译法，归入「可商榷」。措辞、语序之类的风格偏好也归入此类。
- 成段的删节与改写，只并列原文与译文，说明差异，不称为错误。
- 各类型的说明见[类型](/types/)。拿不准属于哪一类时，选最接近的一类即可，维护者会再确认。

## 写作要求 {#writing}

- 只讨论文本，不评价译者的能力、态度或动机。
- 不推测问题的成因。
- 不用讽刺、反问、感叹，不用「竟然」「令人啼笑皆非」之类的措辞。
- 解释以读者理解问题所需为限，不必展开。
- 把握程度与证据相称：有把握的直接说明，没有把握的如实说明。
- 删节与改写的对照，不用「问题」「错误」之类的词。
- 引文以说明问题所需为限，一般不超过一两句。
- 引号用直角引号「」，引号内再用引号时用『』。

## 署名与许可 {#credit}

条目本身不署名。愿意署名的贡献者会列入[贡献者](/contributors/)名单，名单按姓名排序，不记录贡献多少。

提交即表示你同意以 CC BY-SA 4.0 授权本站使用你撰写的说明文字。许可的适用范围见[关于](/about/#license)。
